01 · Overview

An auditable candidate, not a silent change

Training creates a new model version and preserves the active version. It checks the source data and features first, then trains and evaluates against a spatial holdout. The agent should only receive an explained prediction after explicit review and handoff.

Key point: running training does not automatically update heat_offset_model, reconfigure the agent, or promote the candidate. Promotion is outside the current runner.
02 · Data flow

Pipeline stages

The workflow runs through data_plane.pipelines.train_candidate. It uses BigQuery source tables and versioned SQL in data_plane/sql/; artifact names include a unique run ID.

Sources

Checks for data in heat observations, demographics, station temperatures, and daily weather.

heat_observations tract_demographics

Snapshots

Fixes a reference time and snapshots heat and demographic data so the run uses consistent sources.

heat_snapshot_run_id tract_snapshot_run_id

Features

Assigns each observation to the nearest tract centroid, cleans Census values, and computes the offset and spatial split.

training_data_run_id

Train and evaluate

Trains a candidate model, validates its metrics, and tests that a real explanation can be generated.

heat_offset_model_run_id
Each stage records SQL, parameters, job IDs, and results in model_training_events. This workflow appends to the table, which is partitioned by date and clustered by run/stage. The successful terminal state is VALIDATED_CANDIDATE. Run snapshots and feature/residual tables are retained under versioned names; see the BigQuery schema and artifact inventory.
03 · Model and safeguards

Features, target, and validation

Target: heat offset

The offset_f target is the observed temperature minus the mean calculated from training rows only. The agent interprets the result as a difference from that reference, not as an absolute temperature.

Training cells Holdout cells

The split is deterministic, using 0.02° geographic cells and a modulo-five hash. Cells are not shared between training and evaluation; the realized proportion depends on the observation distribution.

Model feature contract

Eight numeric inputs shared with the agent's inference workflow:

latitudelongitudemedian_income poverty_rateno_vehicle_ratemedian_age housing_unitsmedian_year_structure_built

Observed temperature, IDs, cells, imputation flags, and the split flag are excluded from the model's predictive features.

Quality gates

  • One feature row per observation and non-empty training/evaluation splits.
  • No shared cells or null/non-finite values in features or target.
  • Clean income values and an exact match to the eight-feature contract.
  • Candidate MAE must be no worse than the zero-offset baseline.
  • R² ≥ 0.98 blocks the candidate for possible leakage review.
  • Negative R² or MSE worse than baseline is recorded as a warning; every candidate requires review.

Limitations to keep with the result

  • A nearest centroid is an approximation, not a point-in-tract polygon match.
  • There is no spatial buffer between neighboring cells, which may remain correlated.
  • A single campaign does not demonstrate temporal generalization.
  • Socioeconomic attributions are associations, not causal intervention effects.

04 · Follow-up experiments

Tuning and spatial stress test

These are separate, versioned workflows that start from a completed parent run. They preserve the active model and agent. Neither result is an independent production certification or an automatic promotion.

Ridge tuning

data_plane.pipelines.tune_candidate requires a VALIDATED_CANDIDATE parent. It snapshots the parent's prepared features, then compares L2 values 0, 1000, and 10000 across three spatial folds drawn only from the outer training rows. Each inner-fold target anchor is computed from its fitting rows only. Lowest equal-fold mean MSE selects the configuration; ties prefer stronger regularization. 

python3 -m data_plane.pipelines.tune_candidate --parent-run <validated_run_id>
python3 -m data_plane.pipelines.tune_candidate --parent-run <validated_run_id> --execute

After selection is recorded, the chosen model is refit on all outer training rows and scored once on the preserved outer holdout. The event is EXPERIMENT_COMPLETED. That holdout was already inspected during development, so this score is not a new independent certification.

500 m buffer audit

data_plane.pipelines.audit_candidate requires a completed tuning experiment. It removes training readings within 500 m of any holdout reading, verifies no violating pairs remain, recomputes the target anchor, and refits the already-selected L2 value without another hyperparameter search. 

python3 -m data_plane.pipelines.audit_candidate --parent-run <tuning_run_id>
python3 -m data_plane.pipelines.audit_candidate --parent-run <tuning_run_id> --execute

It preserves the holdout and writes parent/buffered residual tables plus aggregate error slices. The terminal event is BUFFER_AUDIT_COMPLETED. Because the fitting rows and target anchor change, this is a stress test—not a replacement score or a new independent test.

What the residual report shows

Row and tract counts, MAE, MSE, signed bias, approximate 90th-percentile absolute error, and zero-offset baseline MAE. Slices cover spatial cells, income imputation, poverty, no-vehicle rate, and tract-centroid distance; groups with fewer than 30 readings are omitted.

The 90th-percentile error is descriptive for this holdout; it is not a calibrated prediction interval. Error slices are diagnostics, not a fairness certification.

Recorded experiment results

  • Ridge tuning selected L2=1000. On the previously inspected 3,218-row holdout, MAE was 1.4626°F and MSE 3.3254 (parent: 1.4984°F and 3.6317); R² was -0.0112 and MSE remained above the 3.2956 zero-offset baseline.
  • The 500 m audit retained 18,018 of 20,168 fitting readings, kept all 3,218 holdout readings, and found no buffer violations. Buffered MAE was 1.4496°F, MSE 3.1382, and R² 0.0458; interpret these as stress-test diagnostics, not independent certification.
05 · Agent handoff

What the agent should receive

The runner returns a training summary for review. A separate inference interface should provide a structured result for ADK/Gemini to compose a municipal response without inventing numbers and while preserving the offset's reference baseline.

A. Training run summary

The process prints JSON with candidate references and evaluation data:

{
  "run_id": "UTC_timestamp_suffix",
  "candidate_model": "...heat_offset_model_<run_id>",
  "feature_table": "...training_data_<run_id>",
  "feature_stats": {
    "row_count": "...",
    "train_rows": "...",
    "eval_rows": "..."
  },
  "metrics": {
    "mean_absolute_error": "...",
    "mean_squared_error": "...",
    "r2_score": "..."
  },
  "zero_offset_baseline": "...",
  "quality_warnings": [],
  "active_model_unchanged": true,
  "promoted": false,
  "promotion_review_required": true
}

Ellipses indicate values computed when the workflow runs; they are not preset metrics.

B. Explained prediction result

data_plane/sql/explain_prediction.sql queries the candidate with coordinates and returns one row with the offset, three attributions, and tract context: 

{
  "predicted_offset_f": 3.4,
  "top_feature_attributions": [
    { "feature": "...", "attribution": "..." },
    { "feature": "...", "attribution": "..." },
    { "feature": "...", "attribution": "..." }
  ],
  "geo_id": "...",
  "total_pop": "...",
  "income_imputed": false
}

Example values are illustrative. Inference must apply the same Census-value fallbacks and validate that the location is within supported coverage.

The agent tool should turn this result into a clear explanation: estimated offset in °F, reference baseline, leading contributors, and relevant demographic context. If given a baseline forecast, it can calculate localized temperature as forecast + offset, clearly labeling it as an estimate.

Safe next steps

  1. Run the plan and review configuration/cost.
  2. Train with --execute in an authorized environment.
  3. Review the candidate, then run tuning and the buffer audit only if appropriate.
  4. Review VALIDATED_CANDIDATE, EXPERIMENT_COMPLETED, or BUFFER_AUDIT_COMPLETED, including warnings and limitations.
  5. Promote only through an explicit decision and a separate procedure.
  6. Update agent tools and test predictions/explanations with the same cleanup logic.
07 · Development evidence · 2026-10-27

Does the model rank hot zones reliably?

The selected use is a human-supervised heat-ranking pilot. The acceptance contract is a draft pending approval, not a production authorization. Heat ranking and vulnerability-weighted policy priority are distinct outputs.

Paired holdout results

  • 3,218 identical held-out readings across 13 spatial cells.
  • 21 tracts meet the draft minimum of 30 readings; seven are excluded.
  • Both candidates recover three of the five hottest measured tracts.
  • Spearman: 0.568 tuned; 0.581 buffered. NDCG@5: 0.687 for both.
  • Tract-mean absolute error: 1.031 F tuned; 1.020 F buffered.

Model fitting anchors are aligned to the same evaluation labels. See the retained ranking report.

Limits and false positives

Both models rank tract 13121007900 first despite its measured mean offset of -1.260 F. Predicted offsets are +1.663 F and +1.364 F.

Omitting one evaluation cell at a time gives Spearman ranges of 0.425–0.665 and 0.442–0.650. Eligible tracts vary from 16 to 21. These are sampling-sensitivity results, not confidence intervals or refitted spatial cross-validation.

The holdout has already been inspected. Observed-point tract means do not validate serving-centroid rankings or future campaigns.

08 · Scenario design · Benefits not yet estimable

Where does planting buy the most relief per dollar?

Selected horizon: ten years from planting. Proposed objective: cumulative human ambient-heat exposure avoided per incremental lifecycle dollar. This is a measurement proposal, not a validated cooling effect.

New data: useful, but not verified

atlanta_tree_planting_optimization adds declared plantable area, marginal planting cost, land-surface temperature and access distances.

  • 109 unique, well-formed GEOIDs.
  • No missing or non-finite values in the six profiled numeric fields.
  • 56 matches among 264 agent-eligible tracts: 21.2% coverage.
  • Declared costs: 300–1,500; area: 593.34–25,000.

Units, source, vintage and whether fields are measured, estimated or synthetic remain unverified. No table description or labels document them. See planting audit evidence and canopy audit evidence.

What a defensible estimate requires

Proposed exposure unit: person-degree-Celsius-hours above an agreed heat threshold, comparing planting against no planting under identical conditions.

  • Annual growth, survival, replacements and maintenance.
  • A defensible causal cooling response and hourly people present.
  • Verified cost units, currency, price year and discount conventions.
  • Feasible sites, uncertainty, overlapping benefits and equity constraints.

Surface temperature is not ambient exposure. Canopy attribution is not the cooling effect of planting. Dividing a heat score by cost does not measure avoided exposure per dollar.

The audit deliberately returns a null relief-per-dollar value and no recommended sites until required evidence is available. See the full scenario contract and updated table schemas. Agent integration, training and promotion are unchanged.
